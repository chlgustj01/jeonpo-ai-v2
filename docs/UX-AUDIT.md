# UX 감사 보고서 — 전포 AI V2 (React 최종본 vs Vanilla)

- 대상: `v2-dev` @ `ede95a7` (Package 5). React V2 `http://localhost:5174/`(WSL Vite 개발 서버, 최신 코드 서빙 확인), Vanilla V2 `http://localhost:3000/`
- 감사일: 2026-11-27. **소스코드·DB·API·환경변수는 수정하지 않았다.**
- 방법: Playwright(Chromium)로 **테스트 전용 새 브라우저 컨텍스트**에서 실제로 클릭, 입력, 이동, 새로고침, 뒤로 가기를 수행했다. 사용자 브라우저 데이터는 건드리지 않았다. 측정 스크립트는 저장소 밖(세션 임시 폴더)에 두었다.
- 화면 폭: 360 / 390 / 768 / 1280px. 스크린샷: `web/screenshots/ux-audit/` (49장)
- **실제 API와 Mock의 구분:**
  - Mock 실행: 분석 응답에는 Package 5에서 기록한 실제 Gemini 응답(9품목 메뉴판, 10개 항목)을 그대로 재생했고, 번역은 합성 일본어로 대체했다.
  - 실제 실행: 390px 전체 여정 1회(실제 분석 14.7초 + 실제 번역 1회). 이어서 같은 이미지로 1회 더 실행했는데, 서버 캐시가 응답해 Gemini 추가 호출은 없었다.
  - 따라서 실제 Gemini 생성 호출은 분석 1회와 번역 1회다.
- 표기: **[측정]** = 브라우저에서 실측, **[코드]** = 코드 확인, **[추정]** = 개선 후 예상값(측정 아님)

## 요약 — 가장 중요한 5가지

1. **[P0] 음식별 위험도가 보이지 않는다.** 10개 음식을 분석해도 화면 상단 배너는 하나뿐이다("RED … Matched: SOYBEAN"). 어떤 음식에 대두가 들어 있는지 카드에 표시되지 않는다. 음식별 판정은 계산되지만 화면에 쓰이지 않는다(`DishResultList.tsx:40-41`). 관광객이 "무엇을 피해야 하는지"를 알 수 없다.
2. **[P0] 음식을 하나 고를 수 없다.** 카드를 눌러도 아무 변화가 없다[측정]. 직원 질문은 위험 음식 9개를 한 문장에 모두 넣어 147자가 된다[측정]. "이 음식을 주문해도 되는지" 묻는 실제 상황과 맞지 않는다.
3. **[P0] 핵심 설정인 알레르기가 온보딩에 없다.** 첫 화면에는 언어, 국적, 맵기, 식단만 있다. 알레르기는 상단의 이름 없는 👤 아이콘 안에 있다. 알레르기를 등록하지 않은 신규 사용자도 결과를 볼 수 있고, 맵기 불일치 때문에 ORANGE "Verification Needed"가 이유 설명 없이 표시된다[측정].
4. **[P1] 지도 → 스캔 연결이 이름과 다르게 동작한다.** 지도 카드의 "Scan Menu Here"는 카메라를 열지 않는다. 그 식당의 **데모 결과**를 바로 보여 준다. 실제 메뉴판을 찍으려면 결과 하단의 "Add a Menu Photo"를 한 번 더 눌러야 한다. 선택한 식당 이름도 스캔 화면에서 사라진다. Vanilla는 "Target: Jeonpo Solgup Samgyeopsal"로 유지했다[측정].
5. **[P1] 상태가 쉽게 사라진다.** 새로고침하면 분석 결과가 사라지고 지도 탭으로 돌아간다. 브라우저 뒤로 가기를 누르면 앱 밖으로 나간다[측정]. 식당에서 사진을 찍고 앱을 전환하거나 잘못 누르면 다시 분석(14.7초, API 비용)해야 한다.

## 1. 전체 서비스 기능 지도

```
[온보딩] 언어 · 국적 · 맵기 · 식단 ─▶ Get Started
   │                                    (알레르기 없음)
   ▼
[상단] FitBridge ─────────────── 👤 프로필 모달: 언어 / 국적 / 맵기 / 식단 / 표준 알레르기 21개 / 커스텀 알레르기
[하단 탭] 🗺️ Map │ 📷 Menu │ 💱 Exchange
   │
   ├─ Map: 필터(전체/식당/카페) · 지도 마커 · 식당 카드(설명, 대표 메뉴, 매장 알레르겐, "Scan Menu Here")
   │        └─ 리뷰: 통계 4개 · 필터 3개 · 리뷰 목록 · 리뷰 작성/수정/삭제   ← 리뷰는 여기에만 있음
   ├─ Menu: 사진 추가 · 미리보기 · Scan · (오류/재시도)
   │        └─ 결과: 출처 안내 · 전체 배너 1개 · 음식 카드 N개(재료, AI 추정 칩, 지식 DB, 먹는 법)
   │                 · 직원 질문(4유형, 한국어 TTS, 정지, 복사) · Add a Menu Photo
   └─ Exchange: 통화 5개 · 양방향 계산 · 기준 환율 목록   ← 메뉴 가격과 연결 없음
```

## 3. React vs Vanilla 비교 [측정 + 코드]

| 항목 | Vanilla V2 (B) | React V2 (C) | 판정 |
|---|---|---|---|
| 하단 탭 | Map / Menu / Guide(TTS) / Rate — 4개 | Map / Menu / Exchange — 3개, 알레르기는 프로필 모달로 | React 개선 |
| 알레르기 설정 위치 | Guide 탭 | 👤 모달 | 둘 다 온보딩에 없음 |
| 지도 → 스캔 | 카메라 화면 + "Target: 식당명" 표시, 셔터를 눌러야 데모 실행 | 즉시 데모 결과, 식당명 없음 | **React 퇴보** |
| "Matched Score: 95%" | **고정 HTML 문자열**(`index.html:402`). 실제 AI 업로드 결과에도 그대로 표시[측정]. 데모 재료 확률(98%, 94%…)도 하드코딩 | 없음 | React 개선(근거 없는 수치 제거) |
| 분석 결과 상단 | 음식명 칩 그리드 — `slice(0, 9)`로 10개 중 9개만, 이름 잘림(`truncate`) | 칩 없음, 카드만 | 둘 다 개요(목차) 부족 |
| 음식별 위험도 | 없음(전체 배너만) | 없음(전체 배너만) | 둘 다 P0 |
| 직원 질문 | 위험 음식 전체 | 위험 음식 전체 | 동일 |
| 오류 처리 | 토스트 | 코드별 문구 + 재시도(Package 5) | React 개선 |
| 콘솔 오류 | 0 | 0 | 동일 |
| 가로 스크롤(390px) | 0 | 0 | 동일 |

## 10. 구체적인 개선 방향

1. **결과 화면 재구성** (P0)
   - 상단: "📍 식당명(있으면) · 10개 중 N개 주의".
   - 그 아래: 위험도순 음식 목록. 한 줄에 한 음식씩, 배지 RED/ORANGE/UNKNOWN/GREEN과 일치 성분을 표시.
   - 행을 탭하면 상세 시트를 연다. 상세에는 재료(AI 추정 칩), 지식 DB(접힘), 먹는 법(접힘), **"이 음식에 대해 직원에게 묻기"**가 들어간다.
   - 기존 `checkDishSafety` 음식별 결과(`DishResultList.tsx:40`)를 그대로 쓰면 되므로 판정 로직은 바꿀 필요가 없다.
2. **직원 질문** (P0)
   - `generateStaffQuestions([selectedDish], profile)`로 음식 1개 기준 문장을 만든다.
   - 선택이 없으면 "위험 음식 N개 한꺼번에 묻기"를 보조 버튼으로 둔다.
3. **온보딩** (P0)
   - 2단계로 나눈다. ① 언어 ② "피해야 할 음식 성분"(AllergyGrid 재사용, 건너뛰기 가능). 맵기·식단·국적은 ②에 포함하거나 나중에 입력하게 한다.
   - 첫 화면에 "메뉴판을 찍으면 내 알레르기 위험을 알려 드립니다" 한 줄을 넣는다.
4. **지도 ↔ 스캔** (P1)
   - `scanStore`에 `locationContext {id, name}`를 둔다.
   - 지도 카드 버튼은 Menu 탭 업로드 화면으로 이동하고, "📍 식당명 메뉴판 촬영" 헤더를 표시한다.
   - 데모는 별도 "예시 결과 보기" 링크로 뺀다.
5. **상태 유지** (P1)
   - `lastAnalysis`·`displayedDishes`·`activeTab`을 sessionStorage에 저장한다. 이미지 원본은 저장하지 않는다.
   - 탭을 해시(`#/menu`)로 반영한다.
6. **다국어** (P1) — 지식 DB 표시 단계에서 "조회 키(영어 원문)"와 "표시 문자열(번역문)"을 분리한다. `Matched:` 접두어와 알레르겐 표시는 `getAllergenDisplayLabel`을 재사용한다.

### 감사 한계
- TTS는 헤드리스 브라우저에서 `speechSynthesis.speak` 호출과 문구·언어(`ko-KR`)만 확인했다. 실제 소리는 확인하지 않았다.
- 실제 기기(iOS Safari, Android Chrome)에서의 터치, 카메라 촬영, 클립보드 권한은 확인하지 않았다. 측정은 Chromium 모바일 에뮬레이션 기준이다.
- 스크린 리더 사용성은 확인하지 않았다.
- 5174 개발 서버와 3000 백엔드는 사용자가 실행한 WSL 프로세스(wslrelay 경유)이며, 그대로 사용했다. 3000 포트에는 이전 세션에서 띄운 Windows 백엔드(PID 21536)도 함께 리스닝 중이다.
- 개선 후 수치는 모두 [추정]이며 구현 후 재측정이 필요하다.
