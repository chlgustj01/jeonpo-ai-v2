# 사용자 알레르기 검색 UI 설계안 (IMP-18 §8)

> 상태: **설계안만, 화면 코드 미수정.** 현재 `index.html`의 알레르기
> 체크그리드(`renderAllergiesGrid`, 19→21개 평면 그리드)는 전혀 바뀌지
> 않았다. 이 문서는 Master DB가 39종(향후 더 늘어날 수 있음)으로
> 확장되었을 때, "체크박스 하나의 화면에 전부 욱여넣지 않기 위한"
> 설계안이다.

## 1. 현재 구조의 한계

`renderAllergiesGrid()`는 `standardAllergens` 배열 전체를 평면 그리드로
렌더링한다. 21개까지는 버틸 만하지만, Master DB의 candidate 18종까지
합쳐 39개, 향후 더 늘어나면 **한 화면에 다 보여주는 것 자체가 사용성을
해친다**(여행자가 급하게 써야 하는 화면인데 스크롤이 길어짐).

## 2. 계층 구조 설계

```
[1depth] 주요 알레르기 기본 표시 (Primary — 처음부터 노출)
  └ 현재 active 21종 그대로 유지(기존 UI 디자인 변경 없음)

[접기/펼치기] "전체 성분 목록 펼치기" 버튼
  └ [2depth] 상위 분류 탭 (biologicalCategory 기준)
       견과류 | 갑각류·연체동물 | 생선 | 과일 | 곡물(gluten) | 기타
       └ [3depth] 각 분류 안의 개별 성분 체크박스 (candidate 포함)

[검색창] 다국어 성분 검색 (항상 노출, 접힌 상태에서도 사용 가능)
  └ 사용자의 현재 UI 언어(state.lang) 기준으로 검색 + 모든 언어 별칭(Allergen_Aliases)도 매칭
  └ 검색 결과에 "표준 등록됨(active)" / "후보(candidate, 아직 기본 목록엔 없음)" 배지 구분 표시
```

## 3. 화면 구성 요소

| 구성 요소 | 설명 |
|---|---|
| **주요 알레르기 기본 표시** | 기존 21개 그리드 그대로(변경 없음) — "대부분의 여행자에게 충분"하다는 기존 설계 철학 유지 |
| **전체 성분 목록 펼치기** | 접힌 아코디언. 펼치면 `biologicalCategory`로 묶인 탭이 나타남. 여기서 candidate 18종(celery, almond, kiwi 등)도 선택 가능 — **단, candidate를 선택해도 UI 라벨에 "국제표준 참고 성분(한국 자체 데이터는 미검증)"처럼 신뢰 수준을 표시**해 active 21종과 체감 신뢰도를 다르게 전달 |
| **다국어 성분 검색** | 입력창 하나, 6개 언어 라벨 + Allergen_Aliases 전부를 대상으로 부분일치 검색(IMP-12의 정규화 유틸 재사용 예정) |
| **상위 분류·세부 성분 탐색** | "견과류" 탭을 열면 호두·잣·아몬드·캐슈·헤이즐넛·피스타치오·피칸·마카다미아·브라질너트가 한 번에 나옴 — **단, 탭으로 묶는 것은 UI 편의일 뿐, "같은 분류니까 전부 위험하다"는 뜻이 아님을 탭 안내 문구로 명시**(사용자 지시: 식품 분류상 같은 그룹이라고 모든 하위 식품에 동일 반응을 가정하지 않음) |
| **선택한 알레르기 표시** | 기존 `allergy-badge`(선택 개수 배지) 유지 + 선택 목록을 다시 접은 상태에서도 "요약 칩(chip)"으로 보여줌 |
| **커스텀 성분 등록** | 기존 `addCustomAllergy()` 그대로 유지(IMP-12에서 매칭 정확도만 개선 예정) |
| **확인되지 않은 커스텀 성분 안내** | 사용자가 입력한 커스텀 성분이 Master DB의 어떤 id/별칭과도 매칭되지 않으면, "이 성분은 저희 데이터베이스에 등록되어 있지 않아 위험도 자동 판정에 반영되지 않습니다 — TTS 카드에는 포함됩니다" 같은 명시적 안내 — **등록 안 됨을 조용히 숨기지 않는다**(IMP-11 §3-5 원칙의 UI 연장) |

## 4. 명시적으로 하지 않는 것

- **국적으로 알레르기를 자동 체크하지 않는다.** 국적/언어 입력은 여전히
  지도 리뷰 통계(`findSimilarTravelerReviews`)에만 쓰인다 — 이 UI 설계
  어디에도 "국적이 OO이면 이 알레르기를 기본 선택"하는 로직을 넣지 않는다.
- **전체 목록을 기본 화면에 한 번에 노출하지 않는다** — 반드시 펼치기
  동작을 거쳐야 candidate 성분에 접근 가능.
- 이번 단계에서 실제 HTML/JS 코드를 작성하지 않는다 — IMP-12 이후 별도
  작업(가칭 IMP-19 혹은 IMP-10 컴포넌트 전환과 함께)으로 미룬다.
