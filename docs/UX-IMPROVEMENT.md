## 3. UI/UX 변경 사항

**결과 화면 정보 순서**(요청 §3):
1. 분석 출처·범위: 식당, 분석 시각, 복원 여부, 범위(coverage), AI 추정 안내, 알레르기 미입력 안내
2. 전체 배너 + 주의 음식 요약
3. 음식 목록: 위험 배지, 첫 이유, DB 확인 칩. 위험도순 정렬, 탭하면 상세로 스크롤과 포커스 이동
4. 선택한 음식: 이름, 배지, 맵기, 이유 목록(⛔ 알레르기 / 🥗 식이 / ⚠️ 교차 접촉 추정 / 🌶️ 맵기 / ❔ 불확실). GREEN은 "일치 없음 — 안전 보장 아님"
5. 지식 DB 추가 확인(프로필 관련만, 기본 표시)
6. 직원에게 묻기(이 음식 / 주의 음식 전체, 4유형, TTS, 정지, 복사)
7. 식재료(AI 추정·사진 글자 칩)
8. ▶ 지식 DB 상세(근거, 출처, 문헌 문구 1회) — 접힘
9. ▶ 먹는 법·문화 — 접힘
10. ▶ 내 식사 기록(리뷰, 식당 연결) — 접힘
- 하단 고정: "이 음식에 대해 직원에게 묻기"

요청 순서(4 직원 질문 → 5 식재료)를 따르되, 프로필과 관련된 지식 DB 경고는 위험 이유 바로 아래에 둠("핵심 위험 경고와 필수 미확인 정보는 기본적으로 보이게 한다").

**그 외 변경:**
- **온보딩:** 목적 문구 → 언어 → 피해야 할 음식(표준 + 커스텀 + "알레르기 없음") → 맵기·식단·국가 → 시작. 시작하면 메뉴 탭으로 이동
- **지도 카드:** "📷 이 식당 메뉴판 찍기"(주 버튼)와 "🧪 데모 결과 보기"(보조 버튼)를 분리하고 내 프로필 일치 강조
- **리뷰:** 데모 리뷰에 "🧪 예시" 배지, 내 기록은 "📱" 배지와 📍 식당 표시. 국가명·맛 태그·맵기 라벨 번역
- **직원 질문 문구:** 지식 DB 관계(예: 참기름 → 참깨)는 "특히 참기름이 들어가는지 알려 주세요"라는 재료 확인으로 묻고, 교차 접촉 질문은 조리도구·기름·공간에 대한 일반 질문으로 분리(요청 §6). 한국어 문장에 영어 재료명이 섞이지 않도록 DB 한국어명만 사용
- **지식 DB 표시:** 조회는 영어 원문 재료(정확도 유지), 화면은 같은 위치의 번역 재료명. 재료 수가 다르면 잘못 짝짓지 않고 원문을 표시

디자인은 기존 vintage 토큰(`vintage-*`)과 컴포넌트(Card, Button)를 재사용했고, 새 UI 라이브러리나 디자인 시스템은 추가하지 않았다.

## 9. 추가 개선 — 메뉴판 가격과 환율 통합 (`27bfa50` 이후)

§2에서 유일하게 남은 연계 실패("메뉴 가격 → 환율 ✗")를 해결한다. 기존 이미지 분석 요청과 기존 환율 기능을 재사용했고, 새 탭, 새 API, 음식별 환산 버튼은 추가하지 않았다.

### 9.1 가격 추출 데이터 구조

분석 API(`api/analyze-menu.js`)의 같은 요청에 가격 필드를 추가했다. 프롬프트는 2.2.0, 응답 스키마는 1.1.0이다. 정규화는 `shared/dish-schema.js`의 `normalizeMenuPrice`가 맡는다.

```json
"price": {
  "status": "exact | range | ambiguous | not_shown | unknown",
  "amount": 9000,                 // exact일 때만
  "min": null, "max": null,       // range일 때만 (min < max)
  "currency": "KRW",              // KRW·USD·JPY·CNY·EUR, 메뉴에 표시된 통화
  "text": "9,000원",               // 메뉴에 적힌 그대로 (40자 제한)
  "source": "menu_text"           // 메뉴판 글자에서 읽음 (not_shown/unknown은 null)
}
```

- **프롬프트 규칙:**
  - 그 음식과 같은 줄·칸에 인쇄된 가격만 사용한다.
  - 가격을 추정하지 않는다. 다른 음식의 가격을 쓰지 않으며, 어느 음식의 가격인지 모호하면 `ambiguous`로 둔다.
  - 음식 사진이나 가격 없는 라벨은 `not_shown`이다.
  - 사이즈별 가격이나 범위는 `range`, "시가"나 읽을 수 없는 가격은 `ambiguous`다.
- **서버 검증:**
  - 금액이 0, 음수, NaN, 문자열이거나 1,000만을 넘으면 → 인쇄 글자가 있으면 `ambiguous`, 없으면 `not_shown`. 절대 0으로 표시하지 않는다.
  - 통화가 없거나 지원하지 않는 통화면 추측하지 않고 `ambiguous`로 둔다.
  - `range`는 min < max여야 한다.
  - 가격은 안전 판정(`dishValidationStatus`)에 영향을 주지 않는다.
- **호환성:**
  - 클라이언트 봉투 검사는 1.0.0과 1.1.0을 모두 허용한다.
  - 가격 필드가 없는 이전 결과는 `unknown`으로 처리하고 가격 UI를 표시하지 않는다.
  - 분석 캐시 키에 프롬프트·스키마 버전이 들어가므로 이전 캐시를 재사용하지 않는다.
  - 번역 요청에는 가격을 보내지 않는다.

### 9.2 환율 공통 상태

- **공통 저장소(`web/src/store/exchangeStore.ts`):** 탭마다 따로 조회하던 `useExchangeRates` 훅을 삭제하고, 앱 전체가 하나의 저장소를 쓴다.
  - 동시에 들어온 요청은 진행 중인 요청 하나를 공유한다.
  - 출처(open.er-api.com)는 하루 1회 갱신된다. 응답의 `time_next_update_utc`까지 localStorage 캐시를 재사용하므로, 새로고침이나 탭 이동 때 다시 조회하지 않는다.
  - 상태는 `live`(출처 갱신 시각 표시: "환율 일 1회 갱신 · {시각} 기준"), `fallback`(기존 안내 "참고 환율 — 실시간 환율을 불러오지 못했습니다" 유지), `loading` 세 가지다. 실패 후 5분 안에는 다시 조회하지 않는다.
- **단위 버그 수정:** 단위를 "1단위당 KRW"로 통일하면서 기존 버그를 고쳤다. 실시간 JPY가 10배 작게 저장되어 "100 JPY ≈ 84 KRW"로 표시되던 문제와, VND 대체값 단위 불일치다. 기존 환율 탭에 있던 결함이며, Vanilla에는 반영하지 않았다.
- **선호 통화:** 프로필에 선택 필드 `preferredCurrency`를 추가했다(기존 저장 데이터와 호환되고, 없으면 null).
  - 선택하지 않았으면 국적으로 추천한다(Japan → JPY 등, 알 수 없으면 USD). 표시 언어와는 독립이다.
  - 메뉴 결과의 통화 선택과 환율 탭의 통화 버튼이 같은 값을 쓴다(`useCurrency` 훅).
  - 온보딩에는 단계나 필수 입력을 추가하지 않았다.
- **파생 계산:** 환산 금액은 저장하지 않는다. "저장된 가격 + 현재 환율 + 현재 통화"로 화면을 그릴 때마다 계산한다(`web/src/lib/money.ts`, Intl 통화 포맷). 세션이 복원되면 가격은 그대로이고 환산은 그 시점의 환율로 다시 계산된다.
